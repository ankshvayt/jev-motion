The small calls in your video edits, made and written down.

An AI decision model makes the small, repeatable calls in your video edits and writes them down, so your AI agent can build the video and you only answer the questions that need a human.

See how it works Get started

Free and open source. Made for videos built with HyperFrames, a tool that makes videos from web pages (HTML).

A short video hides dozens of tiny decisions.

  • Which words in this caption deserve a highlight?
  • That number in the voiceover: does it need a source?
  • Where should the shot zoom in on this screenshot?
  • Does any frame of the finished video look broken?

By hand, it is slow.

Each call takes a moment, but there are dozens in every video, and they come back each time the script changes.

Left to your AI agent, it is costly.

An AI coding agent (an assistant that writes and runs code for you, such as Claude Code or Codex) can make them, but it costs a lot and answers differently from one run to the next.

Jev Motion hands these calls to Jev, a decision model from TypeSafe that answers small, yes-or-no style questions and says how confident it is. Every answer is written down, so the same question gets the same answer next time.

Four decisions it can make for you.

Each one is a handful of small questions with a confidence attached. Here is what each looks like in the example video.

How it works.

jevm is the command behind Jev Motion. Once it is set up, your AI agent runs it for you, one video at a time.

  1. 1

    Your transcript and assets

    The words of your voiceover, with timings, and a list of the screenshots and recordings you plan to show.

  2. 2

    jevm asks Jev small questions

    It turns them into short questions for Jev, or for a local Decider (an optional decision server running on your own computer).

  3. 3

    A decisions list

    Every answer goes into one list, each with its confidence and its lane. Questions for you arrive together.

    decisions.md
  4. 4

    Your agent builds and renders

    Your AI agent settles the calls in its lane, builds the video in HyperFrames from the list, and renders it.

  5. 5

    A frame check

    jevm samples frames from the render and flags any that look wrong, for someone to look at.

Who decides what.

Every answer lands in one of three lanes. The lane depends on how sure the model is and on how risky the call is, so the safe calls flow through and the risky ones stop at a person.

Auto

The build can just use it.

Safe, reversible calls where the model is clearly sure, and asking the question with the options swapped gives the same answer. Your agent can still change it.

For example Highlight “3 hours” in line 1.

Agent

Your AI agent reviews it, and can override.

Calls near the line, answers that change when the options are swapped, anything that needs a look at an image, and anything no model answered.

For example Check the zoom box on the billing screen.

You

Claims and anything risky always come to you.

Your agent collects every question in this lane and sends them all in one message, then waits for your answer before acting on them.

For example Does “3 hours a week” need a source?

Some calls are never automatic.

Whatever the model says and however a project is set up, these never go to the auto lane. The rule is written into the code, not a setting you could flip by accident. Read the never-auto list.

  • Claims and statsA number that sounds measured, and whether a claim matches its source. A person has to stand behind these.
  • Crops and frame checksWhere a zoom sits, and which frames look wrong. Someone has to look at the image.

What it costs, and what stays private.

  • See the price first.

    Every run can show an estimate before anything is sent (--dry-run): how many questions, and roughly what they will cost.

  • Every run has a cap.

    By default $0.10 per run for a short video and $1.00 for a long one. If the estimate is over, nothing is sent. In our tests, a full short-video run cost well under one cent.

  • Your key stays on your machine.

    Your Jev key lives in a local .env file in your project. It is never printed, logged or saved in any output.

  • No key? It still works.

    Without a key, nothing goes to Jev and your agent makes those calls itself. A local Decider, if you run one, can answer some questions at no cost.

Answers are saved, so asking the same question again costs nothing. Two switches keep things closer to home: one sends nothing to TypeSafe, one sends no images at all.

What it doesn’t do.

  • It never edits your video.jevm writes a list of decisions. Your agent, or you, changes the video.
  • It doesn’t replace HyperFrames’ own checks.Keep running them exactly as you do now.
  • It covers HyperFrames only.Other video tools are out of scope.
  • Frame checks cover vertical short videos only, for now.Long, horizontal videos still get highlights, stat checks and crops.

Get started.

You need Python 3.15 or newer, plus ffmpeg and ffprobe (they usually come together), installed on your computer.

Paste this into your agent

Open Claude Code or Codex in your HyperFrames project’s root folder and paste this as your message. The agent will ask you a few questions and never reads your key.

Prompt for your agent
Set up jevm (Jev Motion: bounded decisions for HyperFrames video builds) in the project in your current directory. Do the steps in order. Ask me only what a step says to ask; decide the rest yourself and tell me what you did. Never open, print, grep or copy any .env file.

1. Requirements. Run `python3 --version` (it must be 3.15 or newer) and check that `ffmpeg`, `ffprobe` and `npx` exist. If anything is missing, stop and tell me what to install.
2. Install or update. If ~/tools/jev-motion is missing, run `git clone https://github.com/ankshvayt/jev-motion ~/tools/jev-motion`; otherwise run `git -C ~/tools/jev-motion pull --ff-only`. Only if ~/.local/bin/jevm is missing, run `mkdir -p ~/.local/bin && ln -s ~/tools/jev-motion/jevm.py ~/.local/bin/jevm`. Then run `jevm --help`. If jevm is not on PATH, use `python3 ~/tools/jev-motion/jevm.py` wherever I write `jevm`, and tell me how to add ~/.local/bin to PATH; the CLAUDE.md block (step 9) must then use that same fallback command, and its "`jevm` is on PATH" line must be changed to match.
3. Read ~/tools/jev-motion/README.md, section "Use it from Claude Code or Codex". It is the source of truth for every command; where it differs from this prompt, follow the README.
4. Key. Live answers need my Jev key. I will add one line, JEV_API=..., to .env in the project root myself; if .env already exists, tell me to make sure it has a JEV_API= line instead of adding a second one. Without a key jevm still runs and you decide every row. Do not wait for the key; carry on.
5. Git. If the project is a git repo, add .env and work/ to .gitignore when they are missing.
6. Kit. If jevm-kit/ is missing, copy ~/tools/jev-motion/examples/kit to jevm-kit/. Ask me, in ONE message: is the video vertical (short) or horizontal (long); what is my highlight colour; and one sentence describing my visual style (this becomes qa_context). Edit the kit from my answers: set the highlight colour in manifest.json and in tokens.css (--accent) and in every colour mention in the qa_context text, and put my style sentence into qa_context in both manifest.json and use_when.json. Then run `jevm kit build --kit-dir jevm-kit` and `jevm kit check --kit-dir jevm-kit`.
7. Words. Find the voiceover or source video (ignore the project's own renders, e.g. renders/); ask me which only if more than one real source remains. Run `npx hyperframes transcribe <file> -d .`, which writes transcript.json in the project root. Skip this if transcript.json already exists and I confirm it is current.
8. Assets. List the source screenshots and screen recordings in the project (not the project's own renders) and ask me which to include. Write assets.json in the format the README describes, with a real description of each file, and leave sensitivity at its default unless I say otherwise.
9. Agent instructions. Add the README's agent block ("## jevm (bounded video-build decisions)") to CLAUDE.md without the README's list indentation (so it renders as normal Markdown, not a code block), filling only the setup placeholders: <KIT_DIR>, <WORDS>, <ASSETS>, <short|long> and <AUDIO> (the file you actually transcribed). Leave B, A, ID, V, RENDER.mp4 and <render-stem> as written. Create the file if it is missing; if it exists, append the block under its own heading and never overwrite or reorder what is there. If an AGENTS.md exists, add the same block there too. If a jevm block is already present, update it instead of adding a second one.
10. First run. Run `jevm spec build --project . --format <short or long, as I answered in step 6> --words transcript.json --assets assets.json --kit-dir jevm-kit`, then `jevm spec validate work/jevm/spec.json --kit-dir jevm-kit`, then `jevm plan work/jevm/spec.json --dry-run`. A "Decider unavailable" line is normal when no local Decider runs. If spec build warns that the title is the folder name, mention it in your report (no flag sets it). Show me the cost line and STOP. Do not run a real plan until I say go.
11. Report. End with a short summary: what you created or changed (with file paths), my answers, and what I still need to do (add the key; say go).

Or set it up by hand

Prefer to do it yourself? These steps are what the prompt does. The README has the full detail.

  1. 1

    Install it once

    Clone the repository to a fixed place outside your project, then link it so jevm works as a command.

    Terminal
    git clone https://github.com/ankshvayt/jev-motion ~/tools/jev-motion
mkdir -p ~/.local/bin
ln -s ~/tools/jev-motion/jevm.py ~/.local/bin/jevm
jevm --help

    Optional: put your Jev key in a .env file in your project, as JEV_API.

  2. 2

    Copy the example kit and transcribe

    A kit describes your style: canvas sizes, caption limits, highlight colour. Start from the neutral example, then turn your voiceover into a word-by-word transcript with HyperFrames. If you will zoom on screenshots, list them in an assets.json file too.

    Terminal, in your project folder
    cp -r ~/tools/jev-motion/examples/kit jevm-kit
npx hyperframes transcribe assets/voiceover.wav -d .
  3. 3

    Tell your agent

    Paste the ready-made block from the README into your agent’s instructions: CLAUDE.md for Claude Code, AGENTS.md for Codex. From then on your agent runs the loop and brings you only the questions that need you.

Questions.

Do I need to code?

No. You paste a few commands into a terminal once, during setup. After that your AI agent runs jevm and brings you only the questions that need a person.

What is Jev?

Jev is a decision model from TypeSafe. Instead of writing long answers, it answers small, typed questions (yes or no, pick one, draw a box) and says how sure it is. Jev Motion is an unofficial client for it.

Can I use my own brand style?

Yes. Your style lives in a kit: a small folder that sets your canvas sizes, safe areas, caption limits, highlight colour, how far a crop may zoom, and a short description of your look for the frame checks. Jev Motion ships only a neutral example to copy. How kits work.

What if the AI gets a crop wrong?

Crops are never used automatically. Look at the saved overlay, which shows the box and the area viewers will see. If the box is off, ask again with a more specific description, or give the box yourself as pixel corners on the image. The overlay is redrawn so you can check again.

Does it work with Codex?

Yes. Paste the same block into AGENTS.md instead of CLAUDE.md. jevm is a plain command-line tool, so it does not depend on one particular agent.

What does it cost?

Jev Motion itself is free. Questions sent to Jev are paid for on your own key: you see an estimate before each run, and each run is capped (by default $0.10 for a short video, $1.00 for a long one). Saved answers make re-runs free. In our tests, a full short-video run cost well under one cent.
